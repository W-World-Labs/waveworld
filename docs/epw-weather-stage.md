# EPW weather input stage

This page describes the bounded EnergyPlus Weather (EPW) weather-preparation panel in WaveWorld's Dymola page. It accepts local EPW files for inspection and returns a native parser summary with source metadata. It does not create a weather time series, run EnergyPlus, or calculate building energy use.

## Workflow and limits

Choose up to four files per selection, with a 32 MiB picker limit per file, then select one file at a time for parsing. Browser preflight checks documented missing-value markers and the supported chronology: one data period, one record per hour, minute 60, and contiguous hourly records. Contiguous partial periods are accepted and reported as incomplete; 8760 or 8784 rows are the native parser's annual-complete counts. Other period frequencies or period counts are unsupported. The native job transport also limits serialized input to 1 MiB, so a selected file may still be too large to submit. The app passes raw file text to the existing native EPW operation; it does not implement a separate JavaScript EPW parser. The native parser checks raw structure and produces summaries. Parsing submits raw text as the input to an authenticated Host job.

Export is JSON containing native parser summaries, selected local-source metadata, and an explicit weather-stage scope statement. The metadata includes filename, size in bytes, last-modified time, media type, and `local-file-picker` provenance. No content hash is computed. The export does not contain or emit a validated EPW/weather file, and it must not be treated as one. Numeric values represented in summaries retain the source EPW field units; the stage does not convert units or interpolate missing observations.

Provenance is limited to metadata available from the local file picker and information surfaced from the EPW content, such as location, data-period headers, comments/source text, and per-field source/uncertainty flags. These are recorded claims carried by the file, not independent verification of the original measurement network, station, or weather-data provider. Because no content hash is included, filename and file metadata do not establish byte-level identity. Preserve the original source file and its provider citation when reproducibility matters.

## Time and chronology

An EPW data record uses year, month, day, hour, and minute fields. The EPW `hour` is one-based and ranges from 1 through 24: hour 1 is the interval ending at 01:00, covering 00:01–01:00; hour 24 ends at midnight. The minute field is 1–60. Thus EPW hour values are interval labels, not zero-based clock hours. Do not subtract one from the EPW hour or reinterpret it as a start time without an explicit downstream conversion.

The first eight records describe the location, design conditions, typical/extreme periods, ground temperatures, holidays/daylight-saving information, comments, and data periods. The `DATA PERIODS` header states the number of records per hour and the covered periods. The panel supports one period with one record per hour and contiguous timestamps; partial periods remain available with `annualComplete=false`. EPW files can contain typical-year data whose source years change from record to record and are not required to increase monotonically. Chronology checks therefore follow month/day/hour order and do not require the `year` values to form a continuous increasing calendar series. The calendar `year` field is not generally used by EnergyPlus for simulation chronology.

These conventions follow the official [EnergyPlus EPW data dictionary and auxiliary-program documentation](https://energyplus.readthedocs.io/en/latest/auxiliary-programs/auxiliary-programs.html). EnergyPlus also documents how hourly weather observations relate to simulation timesteps and interpolation in [Tips and Tricks: Output does not match EPW values](https://energyplus.readthedocs.io/en/latest/tips_and_tricks/tips_and_tricks.html).

## Units and missing values

EPW is a text, comma-separated format using SI-oriented field units. Common fields include dry-bulb and dew-point temperature in °C; relative humidity in percent; station pressure in Pa; radiation in Wh/m²; wind direction in degrees; wind speed in m/s; sky cover in tenths; visibility in km; ceiling height in m; precipitable water and liquid precipitation depth in mm; snow depth in cm; and illuminance in lux. The EPW data dictionary is authoritative for the full field order and units.

EPW uses numeric missing-value markers, not one universal null value. Browser preflight and the local native source reject the documented thresholds for supported numeric weather fields and do not substitute a physical-looking value. The dictionary defines field-specific limits: `99.9` for dry-bulb/dew-point temperature, `999` for relative humidity and several weather fields including albedo and liquid-precipitation depth, `999999` for station pressure, `9999` for radiation and selected fields, `999900` for illuminance, `99` for sky cover and selected fields, `99999` for ceiling height, `0.999` for aerosol optical depth, `9` for present-weather observation, and `99` for liquid-precipitation quantity. Values at or above a field's missing threshold are rejected. Consult the source EPW and dictionary when preflight reports a marker; do not replace it with a guessed value merely to pass validation.

EnergyPlus may apply its own missing-weather handling while running a simulation. That downstream behavior does not mean the WaveWorld input stage has imputed those values. See the official [EPW field dictionary](https://energyplus.readthedocs.io/en/latest/auxiliary-programs/auxiliary-programs.html#energyplus-weather-file-epw-data-dictionary) and [EnergyPlus missing weather data guidance](https://energyplus.readthedocs.io/en/latest/guides/input-output-reference/8.1-missing-weather-file-data.html).

## Weather Converter and simulation boundary

EnergyPlus Weather Converter converts supported source weather formats into EPW or EnergyPlus CSV and can produce a statistics file. It may apply conversions and missing-data handling while processing its source; its output should retain the source and conversion provenance. WaveWorld's EPW stage is not a replacement for Weather Converter. The official [Weather Converter documentation](https://energyplus.readthedocs.io/en/latest/auxiliary-programs/auxiliary-programs.html#weather-converter-program) describes its supported inputs and processing behavior.

An EPW file describes outdoor weather. By itself it contains no building geometry, constructions, internal loads, schedules, HVAC systems, controls, or simulation settings. The native summaries and their JSON export do not create a weather time series, close a building-model row, or establish HVAC performance, annual energy consumption, code compliance, or equivalence to an EnergyPlus annual simulation. Those outcomes require a configured building model, a specified EnergyPlus version and run setup, and review of the resulting simulation outputs.
