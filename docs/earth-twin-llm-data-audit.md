# 基于大模型的数据审计平台：多模态、时序、行业数据与地球孪生（Palantir 级能力设计）

> **性质**：能力与产品设计文档（非实现说明）。  
> **定位**：以 LLM 为分析与叙述层，以确定性校验、血缘与对象本体为硬底座，覆盖文本、监控/遥测、图像、时序、结构化文档、多行业数据与地球孪生审计，对标 Palantir 类「对象中心集成 + 管道血缘 + 调查工作台 + AI 辅助」能力，**不**声称复刻 Foundry/Gotham 产品或品牌。  
> **与 WaveWorld 关系**：事实发布与证据绑定复用 [`docs/knowledge-pipeline.md`](./knowledge-pipeline.md) 与 `SourceSnapshot` / `Claim` / `EvidenceBinding` / `KnowledgeRelease`；本设计扩展的是**跨模态审计运行时、对象本体、孪生时间轴与调查工作流**，属于新产品平面，不是把现有知识流水线重命名。

---

## 1. 产品定位与 Palantir 级能力映射

本平台的核心命题是：组织与地球尺度系统每天产生的异构数据（自然语言报告、传感器流、摄像头与遥感图像、时序指标、表格与表单式文档、行业主数据、以及数字/地球孪生中的实体与状态）不能只靠「入库展示」，而必须以**可审计、可溯源、可复核**的方式被持续检查——检查数据是否完整、一致、合规、时间对齐、语义可信，以及孪生世界是否与观测世界发生不可接受的漂移。大模型在此体系中不是「唯一裁判」，而是**把长文本、图像说明、规则与调查假设翻译成可绑定证据的候选断言，并生成人类可读的审计叙事**；真正进入对外「已发布真相」的，必须经过确定性校验、血缘闭合与发布门禁。Palantir 级能力在本设计中被拆成四条可实现的工程能力而不是口号：其一是**对象中心本体（ontology）**，一切审计结论都挂在稳定的业务/物理对象上（站点、资产、人员、批次、地块、传感器、事件、合同条款实例），而不是散落在互不相关的 dashboard 指标里；其二是**集成与变换管道（pipeline / transform）**，原始字节或消息进入系统后产生不可变快照、规范化对象、派生特征与审计运行记录，每一步有版本与输入输出哈希；其三是**调查与运维工作台（investigation / ops）**，分析师或自动代理可以沿着对象关系、时间窗与证据链路钻取，从一条异常打开相关图像、时序、文档段落与孪生状态；其四是**AI 辅助分析（AIP 类）**，LLM 与多模态模型只在明确角色边界内工作（抽取、比对说明、假设生成、报告草稿），输出必须可降级为结构化 Claim 并绑定 SourceSnapshot，禁止「模型说了算」直接改写权威状态。与 Foundry 的差异在于本平台刻意更窄、更审计导向：默认不内建完整应用构建器与任意业务工作流 IDE，而把第一里程碑放在「多模态证据进对象图 → 自动/半自动审计任务 → 冲突可见的发布与复核」；与 Gotham 的差异在于默认场景是工业、能源、环境与地球孪生运维审计，而不是情报产品线的专用战术包。成功标准用可检查语句表述：对任一已发布审计结论，操作者能在有限点击内看到「断言内容、置信度与状态、绑定的原始快照哈希与定位器、所经变换版本、相关对象与时间窗、若有争议则冲突集合」；对任一模态的接入，都有明确的规范化契约与「LLM 可写什么 / 经典校验必须否决什么」的分工；对地球孪生，任一关键状态偏差能关联到观测侧证据与模型侧假设，而不是只显示一个红点。

## 2. 统一审计循环、对象本体与证据法（跨模态共用）

所有模态共用同一条**审计循环**：接入（Connect）→ 不可变捕获（Capture as SourceSnapshot）→ 规范化到对象与属性（Normalize to Ontology Objects）→ 运行审计任务（Audit Jobs：规则、统计、模型、LLM 抽取）→ 产生候选 Claim 与 EvidenceBinding → 门禁（Gate：单位、范围、一致性、权限、血缘完整）→ 状态迁移（candidate / quarantine / validated / released）→ 进入调查工作台或 KnowledgeRelease 类发布物。SourceSnapshot 在 WaveWorld 知识流水线中已定义为「某一时刻对外部源的不可变捕获」，含 locator、capturedAt、contentSha256、captureStatus（locator-only 与 bytes-captured）、可选 license/cursor/provider；本审计平台**直接复用该语义**，并要求审计侧优先 bytes-captured：对文件、图像字节、时序片段导出、API 响应体做内容哈希，避免「只记了 URL、内容已被替换」的假溯源。Claim 复用「关于 subjectId 的结构化 statement + lifecycle state + confidence」模型，但 ClaimKind 在审计域需要扩展（例如 `audit.completeness`、`audit.consistency`、`audit.timeliness`、`audit.compliance`、`audit.anomaly`、`audit.twin_drift`、`audit.lineage_break`），statement 必须是可 JSON 规范化的键值结构（禁止只存自由长文当作唯一 payload）。EvidenceBinding 复用 claimId↔sourceSnapshotId 与 locator（页码、段落、时间戳、bbox、JSON path、表行列），support 取 supports / refutes / context；图像与时序的 locator 必须能指向**具体片段**（帧号/时间区间/像素框），而不是整份文件名。ConflictSet 在审计中尤为关键：两条互斥合规结论或「孪生正常 vs 传感器超限」不得静默覆盖，必须并排可见。KnowledgeRelease 作为「某一审计周期或某一辖区的已发布真相包」仍适用：仅 released claims 可进入对外看板与跨系统消费；LLM 草稿、自动抽取与未过门禁结果永远停留在 candidate/quarantine。对象本体是 Palantir 类能力的真正骨架：建议最小核心类型包括 Entity（组织、人、资产、地块、流域、电网节点）、Observation（传感器读数、影像、报告段落、表单字段）、Process/Event（告警、检修、排放事件、政策变更）、Document（结构化/半结构化文档实例）、TwinState（孪生在时间 t 的状态切片）、AuditRun（一次审计作业的配置、输入快照集、规则版本、输出 claims）、Finding（面向分析师的调查对象，可聚合多条 claims）。行业扩展通过命名空间与可选属性完成（能源、制造、交通、环境、公共设施等），**不**在第一版枚举「所有行业所有表」；各行业通过「对象类型 + 属性 schema + 审计规则包」安装，而不是分叉整套平台。血缘要求贯穿始终：从原始字节哈希到规范化对象版本，再到特征与模型版本，再到 claim 与 release digest，任一 released 结论应能向上游走回不可变证据；血缘断裂本身应成为可发布的 `audit.lineage_break` 类 finding。权限与多租户在设计上与 Host 类产品一致：原始数据、对象、调查工作区与 released 包可有不同可见性；LLM 调用必须记录 prompt/工具版本与输入快照引用（可存侧车审计日志，不必把完整 prompt 塞进 Claim.statement）。与经典校验 vs LLM 的硬分工是本平台可信度的关键：经典层负责哈希、schema、单位/量纲、时间对齐、阈值、统计异常、法规条款编号匹配、重复主键、外键完整性；LLM 层负责非结构化抽取、跨文档语义对照、图像描述与标签建议、调查假设与报告草稿、多语言摘要；**凡是可用确定性规则否决的，禁止只靠模型分数放行**。

## 3. 分模态审计：文本、监控遥测、图像、时序、结构化文档与行业数据

文本审计覆盖政策文件、运维日志叙述、工单描述、合同与报告段落、聊天式告警说明等。审计意图包括：关键实体与义务是否抽取完整、声明是否与结构化主数据冲突、敏感信息是否违规出现、引用条款是否存在、叙事时间线是否自洽、是否与同源时序/图像证据矛盾。接入假设是文本以 UTF-8 字节捕获并哈希，附带来源系统、作者角色、创建/修订时间；规范化时映射到 Document 对象与段落级锚点。LLM 角色是提出候选实体、关系、义务与风险标签，并生成可绑定 quote 的 EvidenceBinding；经典校验负责 PII 模式、必填字段、黑白名单词表、版本比对。示例 finding：合同声称「排放上限 X」但主数据设施额定与历史峰值矛盾；工单关闭叙述与传感器仍超限的时序冲突。监控与遥测审计覆盖指标流、告警、设备健康、日志指标化序列。审计意图包括：采集缺口（丢点、时钟漂移）、阈值策略是否被绕过、告警风暴与根因对象是否可定位、指标命名与单位是否规范、控制回路设定是否异常。接入假设是点位（tag）进入带时间戳与质量码的规范化序列存储，原始批次可导出为可哈希片段；LLM 可对告警文本聚类与根因假设，但**不得**单独判定「传感器坏了」而不给出统计/规则证据。示例 finding：某机组在标定窗口内连续缺测超过 SLA；告警被自动确认但对应孪生态仍越界。图像审计覆盖工业视觉、安防、巡检照片、遥感切片、仪表盘截图。审计意图包括：场景标签是否与工单一致、缺陷/泄漏/侵占是否被漏检、地理与时间元数据是否齐全、与孪生场景渲染是否一致、隐私区域是否合规遮挡。接入假设是图像字节 + EXIF/采集元数据 + 可选矢量标注一并快照；多模态模型输出 bbox/标签必须进入 statement 与 locator，并允许人工修正后重新门禁。经典侧可做哈希去重、分辨率/模糊度、水印与篡改简易检测；LLM/VLM 做语义描述与跨模态对齐建议。示例 finding：巡检照片时间戳落在设备离线窗口；影像显示烟羽而排放时序报正常。时序审计强调「跨源时间对齐」与「模式级异常」：采样率不一致、插值策略未声明、季节性与工况切换未建模、孪生仿真输出与实测序列的漂移指标（RMSE、偏差、相位滞后）超阈。LLM 在此主要用于解释异常片段、对照运维叙述、提出需检查的传感器或模型参数假设，而漂移数值本身由确定性度量计算。结构化文档审计覆盖 CSV/Parquet/JSON/表单/电子表格与半结构化单据：schema 漂移、空值率、主键冲突、编码与小数位、枚举域违规、跨表引用断裂、报表汇总与明细不一致。LLM 可用于从说明文档推断字段语义并映射到本体属性，但 schema 校验与聚合一致性必须由经典引擎执行。示例 finding：日报汇总电量与 15 分钟序列积分不一致超过容差。行业数据审计不穷举行业，而用「规则包 + 对象模板」表达：能源（厂站、馈线、燃料批次、排放因子）、制造（批次、工序、BOM、质量检验）、交通（路段、车次、事件）、环境（断面、介质、标准限值）、城市场景（地块、建筑、许可）。每一行业包声明：必选对象类型、关键属性、审计规则 ID、默认时序/图像源类型、合规引用方式；平台只保证安装与版本化，行业专家维护规则内容。跨行业共性审计包括主数据重复、编码体系冲突、组织边界权限、数据驻留与共享协议是否被管道遵守。所有模态的示例 finding 最终都应收成 Claim + Binding + 可选 ConflictSet，以便进入同一调查时间线。

## 4. 地球孪生（Earth Twin）审计：观测世界、模型世界与漂移闭环

地球孪生审计把「数字孪生是否仍代表真实世界」本身当作一等审计对象。孪生侧包含空间实体（网格、地块、管网、流域、大气柱、基础设施节点）、过程模型（水文、大气扩散、电网潮流、交通流、能量转换——在 WaveWorld 语境下可与能量本体、仿真 job 结果对接）、以及时间轴上的 TwinState 快照；观测侧包含遥感与近感图像、地面传感器时序、巡检与社会报告文本、行政与产业结构化登记。审计意图不是追求像素级完美一致，而是在声明的**有效域、分辨率、工况与不确定度**内，检测不可接受的偏差、过时状态、未吸收的观测、以及用错误证据支撑的「孪生健康」声明。典型循环是：在时间窗 \([t_0,t_1]\) 收集观测快照集 O 与孪生状态/仿真输出集 T → 运行确定性对齐（空间重投影、时间重采样、单位换算）→ 计算漂移指标 D → 规则与统计门禁产生候选 claims → LLM 结合运维文本与图像说明生成调查叙事与假设 → 分析师确认或 quarantine → 发布 released 包驱动运维动作（重新标定、派单、模型再训练触发、对外披露）。与 WaveWorld 的衔接点在于：仿真与实验路径已有 JobSpec/结果与知识发布机制，孪生审计可以把「某次仿真输出 artifact」与「对应实测序列」同时打成 SourceSnapshot，把「模型在工况 C 下误差低于 ε」写成 Claim，并在漂移超限时用 ConflictSet 保留旧发布与新质疑。地球孪生审计还必须处理多尺度：局部设施孪生与区域环境孪生共用对象 ID 策略（稳定 URI/ codification），避免同一变电站在电力本体与地理本体中无法连接；时间上区分「观测延迟」「仿真时效」「发布滞后」，防止用过期孪生状态做实时合规判断。示例 finding 集合应覆盖：关键传感器停报导致孪生进入外推模式却未标记；排放清单与遥感反演数量级冲突；洪水演进仿真峰值时刻与实测水位站相位差过大；土地覆被分类更新未传播到下游风险模型；跨部门数据共享协议限制导致血缘在边界处断裂。LLM 在孪生审计中的正确用法是解释「为何漂移可能发生」与「下一步查哪些对象」，而不是直接改写 TwinState；状态写回必须走受控 API 与权限，并留下审计 run 记录。

## 5. 运行时架构、审计作业与调查工作台

逻辑架构分为六层，可分服务实现也可先单体模块化：接入层（连接器：对象存储、消息总线、数据库 CDC、邮件/网盘、摄像头/NVR、遥感目录、企业 API）；捕获层（生成 SourceSnapshot，强制哈希与许可证元数据）；本体与规范化层（ETL/流处理把原始记录变成对象属性与关系边，产出可版本化的对象图）；特征与指标层（时序特征、图像嵌入索引、文本段落索引——嵌入用于检索，不作为唯一审计结论）；审计执行层（规则引擎、统计/异常检测、可选 w-sim/仿真对照作业、LLM/VLM 抽取与对照代理）；发布与调查层（Claim 生命周期、ConflictSet、KnowledgeRelease 或等价审计发布包、分析师 UI、API）。审计作业（Audit Job）建议有显式规格：目标对象选择器或数据集版本、时间窗、规则包与模型版本、是否允许 LLM、资源档（CPU/GPU）、输出 claim 类型白名单；作业结果写入 AuditRun 记录，失败要可重放。与 WaveWorld Host 的 jobs 平面可类比：批处理审计可走 claim→run→complete 语义，但审计结论的「发布」仍走知识生命周期，避免把「任务成功」误当成「事实成立」。调查工作台最小能力包括：对象主页（属性、关系、时间线、相关 findings）、证据查看器（文本高亮、图像框、时序刷选区）、血缘图（上游快照与变换）、冲突面板、LLM 侧写（明确标注非权威）、行动建议列表（工单链接占位）。自动化方面可设分级：L0 纯规则、L1 规则+统计、L2 增加 LLM 抽取需人审、L3 允许 LLM 提议行动但仍人批；默认生产路径避免 L3 无人值守改写权威数据。性能与成本上，LLM 只对「检索召回的片段与告警子集」调用，先用经典过滤器缩小集合；图像与长时序优先本地/边缘预过滤。安全上区分训练数据、生产证据与模型输出的保留策略，满足行业留存与删除权；密钥与模型端点配置不进 Claim。

## 6. 与 WaveWorld 知识流水线的复用边界、实施阶段与完成定义

**复用（直接采用）**：`SourceSnapshot`、`Claim`、`EvidenceBinding`、`ConflictSet`、`KnowledgeRelease` 的版本化与生命周期；`candidate→quarantine→validated→released` 状态机与「Atlas/对外只消费 released」原则；确定性 `sha256` 发布摘要；OpenAlex/Crossref 类文献接入作为「文本/文献证据」的一条已有管道；效率/SI 等门禁模式可推广为「领域校验门禁插件」。**扩展（本设计新增）**：多模态 locator（时间区间、bbox、频段）；审计域 ClaimKind 与行业规则包；对象本体与对象图存储；AuditRun/Finding 调查对象；地球孪生漂移度量与观测-模型对齐；连接器与规范化管道；调查工作台 UX；LLM/VLM 工具调用审计日志。**不复用或暂不耦合**：WaveWorld 教学 L0 仿真页、能量转换矩阵的产品导航本身不是审计 UI；w-sim 解算器矩阵是「可被审计与对照的计算后端」而非本审计平台的替代；不得把 LLM 草稿直接写入 KnowledgeRelease。实施建议分四期：第 1 期打通「文件/表/指标批量 → Snapshot → 规则审计 → Claim 生命周期 → 只读调查列表」，文本 + 结构化 + 基础时序；第 2 期图像与多模态 locator、告警关联；第 3 期行业规则包框架与 2～3 个示范行业；第 4 期地球孪生漂移闭环与仿真/观测对照作业。完成定义用可演示场景表述：给定一套含文本报告、指标 CSV、巡检图像与孪生状态导出的演示包，系统能自动产生至少一类完整性 finding、一类一致性 finding、一类孪生漂移 finding，全部带证据绑定与可验证发布摘要，并在冲突场景下展示 ConflictSet 而非覆盖；分析师可从 finding 跳到原始字节哈希一致的快照片段。非目标再次强调：不实现完整 Palantir 产品克隆、不在本设计阶段交付生产连接器代码、不训练专用大模型、不把「各行业」做成无限表清单，而是做成可安装的规则与本体扩展机制。该文档作为后续立项、Gitea epic 与 `/goal` 执行的范围基准；实现时应先固化契约扩展与门禁插件接口，再铺连接器与 UI，避免先堆模型演示导致无法审计。
