# Abaqus material card to W-Sim material point

The WaveWorld importer reads a deliberately narrow, standalone material card. It accepts one `*MATERIAL, NAME=...`, one isotropic `*ELASTIC` row, and one `*PLASTIC` table. Abaqus defines `*MATERIAL` as the start of a named material definition; the importer uses that name as a label only. Abaqus allows material behavior options in a material block in any order, but this reader requires exactly one of each supported keyword and rejects every other keyword and option. It is not an Abaqus input-deck or model parser. See the official [*MATERIAL](https://docs.software.vt.edu/abaqusv2025/English/SIMACAEKEYRefMap/simakey-r-material.htm), [*ELASTIC](https://docs.software.vt.edu/abaqusv2025/English/SIMACAEKEYRefMap/simakey-r-elastic.htm), and [*PLASTIC](https://docs.software.vt.edu/abaqusv2025/English/SIMACAEKEYRefMap/simakey-r-plastic.htm) keyword references.

For isotropic elasticity, the first `*ELASTIC` data values are Young’s modulus `E` and Poisson’s ratio `nu`. For isotropic metal plasticity, each `*PLASTIC` row gives yield stress followed by equivalent plastic strain; the first plastic strain is zero and later plastic strain values increase. Abaqus does not prescribe a unit system: use one internally consistent system for `E`, yield stress, and every stress supplied or returned; `nu` and strain are dimensionless. The importer does not convert units. These meanings and ordering follow the Abaqus keyword definitions.

The parsed hardening rows are stored as `[yieldStress, equivalentPlasticStrain]`, matching Abaqus order. The caller maps these properties to the pinned W-Sim module `sw-calculix-plasticity`: `E`, `nu`, and the first-row yield stress map to `E`, `nu`, and `yieldStress`; with two or more rows, `hardeningCurve` rows are reordered to `[equivalentPlasticStrain, yieldStress]`. A one-row Abaqus table maps to `hardening: 0`, the module's perfectly plastic isotropic law. The material card carries no load history: the caller must provide `strainIncrements` as six-component total-strain increments in `[exx, eyy, ezz, gxy, gxz, gyz]` order, with engineering shears `g=2εij`. Stress shear is tensor shear, ordered `[sxx, syy, szz, sxy, sxz, syz]`.

The module returns `history` for each increment, including accumulated `totalStrain`, tensor `stress`, tensor `plasticStrain`, `equivalentPlasticStrain` (PEEQ-like material-point history), `vonMises`, `yielded`, `plasticMultiplier`, and plastic dissipation fields. The summary includes final stress, plastic strain, equivalent plastic strain, von Mises stress, and cumulative plastic dissipation, along with step counts. These are local constitutive outputs for one small-strain, isotropic-elastic, associative J2 material point with isotropic hardening. They are not a full Abaqus response: there is no mesh, element or section integration, assembly, equilibrium solve, temperature/rate dependence, damage, or general Abaqus keyword support. The result is not Abaqus execution or vendor parity.
